01 · The decision

Should every derived column inherit its source's tag?

Tag propagation copies governed tags (like pii) from a source column to the matching derived column. Now that it runs on classic compute too, far more derived tables are in scope. But not every transform keeps data sensitive: a SUM() of salaries or a salted hash usually isn't the raw value. Imagine I'm the PM deciding the default per transform type.

Customer problem

"My masks spread to columns that aren't sensitive anymore."

Governance admins want zero untagged PII downstream. Analysts get blocked when a column mask follows a monthly aggregate that no longer identifies anyone. Both sides file tickets; stewards drown in both.

pinned to: governance · analyst friction

Proposed change

Transform-aware propagation

  • Auto: copy the tag (today's behavior).
  • Suggest: copy as a pending tag (still enforced); a steward confirms or clears it.
  • Drop: don't carry the tag; record the lineage only.

Pick one default per transform type from a Bayesian read of a steward audit.

Success metric

Expected harm per derived column ↓

Harm units: 1 = one wrongly masked column (an analyst unblock ticket). A missed sensitive column costs cleak units (slider). Each steward review costs 0.15.

04 · The math, from my Monte Carlo course

Bayesian updating, one transform at a time

Prior × likelihood

Before the audit I believe θ (the chance a column is still sensitive after, say, an aggregate) follows a Beta with mean m and strength s. The audit is Binomial: k of n checked columns were still sensitive.

θ | k ~ Beta(ms + k, (1−m)s + n − k)

Beta prior + Binomial data stays Beta. That is the conjugate shortcut.

Shrinkage

The posterior mean is a weighted average of the prior mean and the audit rate:

E[θ|k] = (s·m + n·(k/n)) / (s + n)

With 5 audited hash columns the prior still pulls hard. With 200, the audit wins. Drag the audit slider and watch the lanes tighten.

Decide under uncertainty

For each lane I draw 2,000 θ values from the posterior (Beta draws built from two Gamma draws), compute the harm of auto, suggest and drop for every draw, and average. The lowest expected harm becomes the default. The 90% credible interval uses the 5th and 95th percentiles of the draws.

default = argmina (1/N) Σ harm(a, θi)

05 · How I'd run it on real data

From audit table to posterior in two cells

Table and column names are illustrative.

SQL: audit counts per transform

-- one row per steward-checked derived column
SELECT
  transform_type,
  COUNT(*)                                   AS n_audited,
  SUM(CASE WHEN still_sensitive THEN 1 END)  AS k_sensitive,
  ROUND(AVG(CAST(still_sensitive AS INT)),3) AS raw_rate
FROM gov_lab.audit.derived_column_reviews
WHERE source_tag = 'pii'
  AND reviewed_at >= current_date() - INTERVAL 30 DAYS
GROUP BY transform_type
ORDER BY raw_rate DESC;

Python: posterior draws + default

import numpy as np
rng = np.random.default_rng(102)
m, s, c_leak, c_rev, miss, L = .7, 6, 20, .15, .02, .999
audit = spark.table("gov_lab.audit.transform_counts").toPandas()

def harm(theta):
    auto    = L*(1-theta) + (1-L)*theta*c_leak
    suggest = L*(c_rev + theta*miss*c_leak + (1-theta)*.10) \
              + (1-L)*theta*c_leak
    drop    = theta*c_leak
    return np.vstack([auto, suggest, drop]).mean(axis=1)

for r in audit.itertuples():
    th = rng.beta(m*s + r.k_sensitive,
                  (1-m)*s + r.n_audited - r.k_sensitive, 2000)
    pick = ["auto","suggest","drop"][harm(th).argmin()]
    print(r.transform_type, pick, np.percentile(th,[5,95]).round(2))
